# Cloud Resource Optimization – V3 Evaluation Patch

## Files to replace
Copy these files into the project root, overwriting the existing files:
- `main.py`
- `cloud_simulator.py`
- `scenarios.py`

No model retraining code or dataset files are changed.

## Changes
1. All three strategies are scored on the same final 476 observations of the 500-row scenario window. The preceding 24 observations are retained as AI prediction history.
2. Baseline, threshold, and AI SLA violations now count a breach when either CPU **or** RAM utilization exceeds the configured SLA threshold.
3. AI SLA violation rate uses the actual number of evaluated observations as its denominator.
4. The AI prediction-failure fallback now uses the same percentage-point units as the normal prediction path and records SLA breaches.
5. Threshold scaling starts with 100 CPU and 100 RAM capacity per instance, matching the baseline and AI autoscaler's initial per-instance capacity.
6. Flash-sale scenario generation is deterministic with seed 42.
7. The final experiment summary is aggregated across all five scenarios. Utilization, SLA and efficiency are equal-weight means across scenarios; costs are summed across the five scenario runs.
8. Removed the unsupported hardcoded claim of 87% cost reduction.

## Important interpretation limits
- This patch improves evaluation consistency and reporting; it does **not** establish that AI is the best strategy.
- Cost values remain outputs of the project's illustrative cost model. They are not actual AWS/Azure/GCP bills.
- The optimizer still has a design limitation: the autoscaler's instance-count decision and the optimizer's aggregate CPU/RAM capacity calculation are not fully unified. Treat per-instance allocation interpretation cautiously; this should be the next algorithmic improvement.
- The five scenarios are synthetic perturbations of a 500-row held-out trace window, not five independent real-world datasets.
- Dataset timestamps are relative five-minute indices generated by the adapter, not observed source timestamps.
- The LSTM scaler is fitted on the training partition, as in V2. Do not tune algorithm thresholds against the held-out test window.

## Apply
1. Back up your current `main.py`, `cloud_simulator.py`, and `scenarios.py`.
2. Extract this ZIP into the project root and overwrite those three files.
3. Run:
   ```powershell
   python -m compileall -q .
   python main.py
   ```
4. Share the new `outputs/scenario_results.txt`, `outputs/final_experiment_summary.txt`, and any traceback if it fails.

The results will differ from V2 because the evaluation horizon, SLA definition, threshold instance capacity, and scenario reproducibility have changed.
